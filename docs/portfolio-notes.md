## 1. 무료 판정 4상태 (BUG-03, D안)

- **문제:** 같은 행사가 목록에서는 "유료", 홈·상세에서는 "무료"로 나왔다. 목록은 `IS_FREE === '무료'`만 보고, 홈·상세는 `USE_FEE`에 '무료'가 들어 있어도 무료로 봤다. 요금 필터는 엄격한 쪽을 따랐다.
- **데이터/근거:** 실데이터 1,000건(2026-11-09) 분류 결과 **무료 681 / 유료 282 / 일부 무료 18 / 가격 상이 10 / 확인 필요 9**. "무료/유료" 두 값으로는 "어린이 무료, 성인 1만 원" 같은 행사를 정직하게 표시할 수 없었다.
- **선택지:** A~D (두 규칙 중 하나로 통일하는 안들과, 상태를 나누는 안).
- **결정:** D안 — 한 규칙(`utils/fee.ts` `feeKind`)으로 **무료 / 유료 / 일부 무료 / 가격 상이** 네 배지 + 판단 불가는 배지 없이 요금 글자만("확인 필요"). 목록 배지·필터, 홈 카드·히어로·무료 탭, 상세 관람료가 모두 이 규칙을 쓴다.
- **결과:** 화면 사이 불일치 제거, 회귀 테스트 `e2e/fee.spec.ts`. 배지 색은 무료 = accent-text 채움 + 흰 글자(5.95:1), 유료 = night 채움 + 흰 글자(16.71:1), 일부 무료·가격 상이 = 테두리형.
- **제안 / 결정:** 선택지 제안: Claude / 결정: 사용자(D안). 배지 색 조합: 변경 요청은 사용자, 구체 색 조합의 최초 제안자는 **확인 필요**.
- **화면:** Before `before-main/events-1440.png` → After `qa/events-1440.png`

## 2. 행사 ID 안정화 (BUG-08)

- **문제:** 행사 주소와 찜이 **배열 순서 번호**(`events[Number(id)]`)를 ID로 썼다. API 순서가 바뀌면 링크·찜이 다른 행사를 가리켰고, 홈은 필터된 목록의 번호를 저장해 처음부터 틀린 찜도 있었다(BUG-01).
- **데이터/근거:** `HMPG_ADDR`의 `cultcode`가 19,750 / 19,750건 모두 있고 중복 0(2026-11-09 실데이터).
- **선택지:** 몇 가지 ID 후보와 이전 방식 (A안 = cultcode + 해시 예비).
- **결정:** A안 — `cultcode`, 없으면 `제목+시작일+장소`의 FNV-1a 해시(`h…`). 기존 찜은 1회 이전: 포스터 URL → 제목+시작일 → 제목+장소 순서로 다시 찾고, 못 찾으면 지우지 않고 "정보를 불러올 수 없는 행사"(종료일이 지났으면 "종료된 행사")로 남김. 원본은 `nolseoul-favorites-v1-backup`에 백업.
- **결과:** 오래된 링크(`/event/12`)는 "오래된 링크" 안내. 2026-11-11에는 같은 방식을 문화공간·야경에도 적용(`s<NUM>`/`n<NUM>`, NUM 고유: 1,100/1,100, 51/51).
- **제안 / 결정:** 선택지 제안: Claude / 결정: 사용자(A안, 사라진 찜은 남기기, "종료된 행사" 표시). 공간·야경 확장(2026-11-11)은 사용자 지시, 세부(접두어 ID, 이름 단독 재매칭 단계)는 Claude가 야간 작업 중 결정 — `docs/overnight-report.md`에 되돌리는 방법 기록.
- **화면:** After `mypage/1440-full.png` (종료된 찜·불러올 수 없는 찜 카드)

## 3. 데이터 범위 (TECH-10)

- **문제:** 행사 API 첫 1,000건만 받고 있어 진행 중인 행사가 빠졌다.
- **데이터/근거:** 행사는 시작일 순서로 정렬돼 있어 **오래 진행 중인 행사가 아무 위치에나** 있다 — 4,000번째 이후에도 진행 중 행사 7건. 서울시 API의 DATE 파라미터는 "그날 진행 중" 필터가 아니라 DATE 필드 글자 검색이라 쓸 수 없었다.
- **선택지:** A(앞 일부만) / B(1~4,000건 병합 + 1시간 캐시) / 최종안(전체 + 긴 캐시).
- **결정:** B안을 먼저 적용했다가 위 7건 때문에 최종안으로 — **세 API 모두 전체 페이지 수신 + CDN 24시간 캐시**, 행사는 "오늘 진행 중 + 3개월 내 시작"만 응답. 쓰는 필드만 보내기(공간 −13% 등). 오래된 캐시에도 끝난 행사는 브라우저에서 한 번 더 제거.
- **결과:** 19,750건 중 331건(진행 중 201 / 3개월 내 130), 서울시 API 호출은 엣지 지역당 하루 한 번 수준(갱신 1회 ≈ 23회 호출).
- **제안 / 결정:** A/B 선택지 제안: Claude / B안 결정: 사용자. 최종안(전체 + 24시간)은 결정: 사용자, 최초 제안자는 **확인 필요**.
- **화면:** After `qa/events-1440.png` (총 N건)

## 4. 상태·포인트 컬러 층 (DESIGN §2.0.1)

- **문제:** 탠저린이 반투명(알파)으로 여기저기 쓰여 hover·선택 상태가 화면마다 달랐고, 탠저린 위 흰 글자는 대비가 부족했다.
- **데이터/근거:** 대비 계산 — 탠저린 위 잉크 4.91:1(통과), 탠저린 위 흰색 미달, tangerine-deep 글자 on bone 5.33:1, accent-tint 위 탠저린 글자 3.08:1(미달).
- **선택지:** 표 형식으로 정리한 결정 항목 C1~C5.
- **결정:** C1 탠저린 위 글자는 크기와 상관없이 잉크 / C2 히어로 "in"·지도 프로모·푸터 점·지도 강조 핀은 유지하고 사용처 목록에 추가 / C3 작은 강조 글자는 별도 토큰 `accent-text` / C4 `accent-tint`는 미리 섞은 불투명 색 / C5 이미 탠저린인 것의 hover는 `accent-press`. **탠저린 사용처는 목록에 있는 곳만**(현재 10곳).
- **결과:** 반투명 브랜드색 금지, 상태 토큰 표, 컴포넌트 상태 표. 이후 모든 화면(검색, 마이페이지, 코스추천 버튼 포함)이 이 규칙으로 만들어짐 — 예: 코스추천 버튼은 시안의 탠저린 + 흰 아이콘 대신 CTA 규칙(잉크 → hover 탠저린 + 잉크).
- **제안 / 결정:** 층을 만들자는 요청과 "표 먼저": 사용자 / 표와 C1~C5 초안: Claude / 결정: 사용자.
- **화면:** Before `before-main/home-1440.png` → After `qa/home-1440.png`

## 5. 히어로 가독성

- **문제:** 포스터 위에 제목·메타를 올리면 포스터마다 글자가 묻혔다. 한편 "포스터 위에 글자 금지"는 카드 규칙이었다.
- **선택지:** A / B / C (오버레이·배치 방식 조합).
- **결정:** A+C(필요하면 B) — 히어로 배너만 예외: 포스터 `cover` + **하단 45% 그라데이션**(투명 → night 70% → 92%) + 캡션(분류 칩, 제목, 메타) + 글자 그림자. 카드 썸네일은 그대로 "3:4 cover, 위 기준, 글자 없음". 예외를 DESIGN.md Poster rule에 문서화.
- **결과:** 어떤 포스터에서도 캡션이 읽힘. 규칙의 예외가 문서로 남아 다음 화면에서 번지지 않음.
- **제안 / 결정:** 선택지 제안: Claude / 결정: 사용자(A+C, 문서화 지시).
- **화면:** Before `before-main/home-1440.png` → After `qa/home-1440.png`, `qa/home-390.png`

## 6. 야경 "밤이 오면 켜진다"

- **문제:** 야경명소 데이터(51곳)에는 사진·평점이 없고 운영시간이 자유 문장("일몰 30분 후 점등 ~ 23:00 소등", "24시간", "하절기/동절기 …")이다. 그대로 나열하면 "지금 가면 켜져 있나?"에 답하지 못한다.
- **데이터/근거:** 일몰 시각을 NOAA 식으로 계산해 한국천문연구원(KASI) 값과 비교 테스트(일치). 운영시간 문장을 규칙으로 해석(`utils/night.ts`): 점등 중 / HH:MM 점등 / 소등 / 운영 중 / 운영 종료.
- **선택지:** 시안(design-ref `page-night.jsx`)의 콘셉트를 실데이터로 어떻게 옮길지 (A 목록형 + B 빛 지도형 등, 달 표시 여부).
- **결정:** `/night` 신설, 콘셉트 "밤이 오면 켜진다", A+B, 달 표시 없음, 일몰 기반 상태 배지, 헤더 내비 추가. 이후 **"켜진 곳"(점등 중만)과 "갈 수 있는 곳"(운영 중)을 분리**해 야경 페이지·지도·Live Bar가 같은 정의를 쓰도록 통일. 공식 데이터가 틀린 곳은 출처를 적은 수동 규칙 파일로만 보정.
- **결과:** 일몰 전에는 "곧 켜져요", 해가 지면 실제로 켜진 곳 수가 Live Bar·검색 칩·마이페이지 통계에 같은 숫자로 나옴.
- **제안 / 결정:** 콘셉트 문구 출처: 시안 design-ref(작성자 **확인 필요**) / 페이지 구성 제안: Claude / 결정: 사용자(A+B, NOAA+KASI 테스트, 배지, 달 없음, 경로·내비). "켜진 곳/갈 수 있는 곳" 분리: 결정: 사용자(문제 제기자 **확인 필요**).
- **화면:** After `qa/night-1440.png`, `qa/night-390.png`, `qa/map-1440.png`

## 7. 야경 사진 매칭 기준

- **문제:** 야경 카드가 모두 그래픽이었다. 관광공사 사진을 쓰되 **다른 장소·낮 사진·다른 지역 사진을 잘못 붙이면 안 됐다.**
- **데이터/근거:** 관광공사 관광사진 API를 스크립트로만 호출(앱은 호출 안 함, 1회 실행 ≈ 120회 / 일일 한도 1,000회). 후보를 표로 검토.
- **선택지:** 엄격 기준(4조건) / 완화 기준(태그·"밤/달빛"도 야경 근거로, 일부 이름 규칙).
- **결정:** 4조건 — ① 제목·촬영장소에 장소의 핵심 이름 ② 촬영장소에 "서울" 또는 해당 구 ③ 다리 등 흔한 단어는 전체 이름 필요 ④ 다른 지역명 없음 + 야경 사진. 엄격 기준으로는 사진이 거의 나오지 않아 원인을 진단한 뒤 **완화 기준으로 15곳**, 접촉 시트로 눈으로 재확인. 정적 매핑 파일(`data/night-photos.json`), 표기 "사진: 한국관광공사 · 촬영 {촬영자}", 공공누리(이용허락범위 제한 없음).
- **결과:** 51곳 중 15곳 사진, 나머지는 같은 틀의 빛 지도 그래픽(사진 로드 실패 시도 그래픽으로 대체).
- **제안 / 결정:** 조사 요청·사진 종류·정적 매핑·표기 방식: 사용자 / 4조건 초안과 완화안: Claude / 결정: 사용자(4조건 승인 → 완화안 15곳 채택). 엄격 기준의 정확한 매칭 수는 **확인 필요**.
- **화면:** After `qa/night-1440.png`

## 8. 검색 바로 가기에서 숫자 제거

- **문제:** 시안의 바로 가기 칩에는 "이번 주 무료 행사 68" 같은 숫자가 있었다. 칩마다 다른 기준으로 센 숫자는 실제 목록 페이지에서 보이는 숫자와 어긋나기 쉽고(필터를 넘기지 않으므로), 유지 비용이 든다.

- **제안 / 결정:** 시안과 다른 점 목록 작성: Claude / 숫자 제거와 야경 예외 결정: 사용자 / 숫자 제거를 처음 제안한 쪽: **확인 필요**.
