### [4] 공간·야경 안정 ID
- **결정:** ID = 공간 `s<NUM>`, 야경 `n<NUM>`. API에 FAC_CODE가 없음(원본 필드 목록 확인). NUM은 실데이터에서 공간 1,100/1,100, 야경 51/51 모두 겹침·빈 값 없음, 배열 순서와도 다름.
  **이유:** 접두어를 붙여 옛 순번 ID(숫자만)와 절대 헷갈리지 않게 함 → 이전 대상·오래된 링크를 확실히 구분.
  **위험:** NUM이 서울시 데이터 갱신 때 다시 매겨지는지는 하루 데이터로만 확인해서 **장기 안정성은 미확인**. 며칠 뒤 같은 장소의 NUM이 같은지 한 번 비교해 보는 걸 권장.
  **되돌리기:** `utils/placeId.ts`의 `spaceId`/`spotId`만 바꾸면 전체가 따라감(이전은 다시 실행되지 않으므로 플래그 `nolseoul-favorites-places-version` 삭제 필요).
- **결정:** 재매칭 순서 = ① 이름+주소가 정확히 1곳 ② 이름이 정확히 1곳. 못 찾거나 여러 곳이면 `legacy-<옛 id>` + orphan으로 남김(삭제 안 함).
  **이유:** 지시대로 이름+주소가 기본이고, 주소 표기만 바뀐 경우를 살리려고 이름 단독(유일할 때만) 추가. 실데이터에서 이름이 겹치는 공간은 1,100곳 중 4개 이름뿐.
  **되돌리기:** `utils/placeFavoritesMigration.ts` `pick()`에서 이름 단독 단계 제거.
- **결정:** 백업 키 `nolseoul-favorites-v2-backup`, 완료 플래그 `nolseoul-favorites-places-version`="1"(행사 이전 플래그와 독립).
- **결정:** 이전 컴포넌트는 옛 공간·야경 찜이 있을 때만 붙어서 공간 데이터(1,100곳, 약 2MB)를 모든 페이지에서 불러오지 않음.
- **결정:** 옛 순번 링크(`/space/12`)는 행사 때와 같게 "오래된 링크라 문화공간을 찾을 수 없습니다." 표시. 옛 `/night?spot=3`, `/map?...&spot=3`은 조용히 무시(목록만 보임).

### [5] AI 코스추천 리모컨
- **결정:** 패키지 `@anthropic-ai/sdk` 1개 추가(공식 SDK). 모델 `claude-opus-5-5`, effort `low`, JSON 스키마 출력, 거절 시 서버 측 `fallbacks: "default"`.
  **이유:** 공식 SDK 사용이 원칙이고, 코스 3곳 고르기는 짧은 작업이라 effort low로 비용·지연을 줄임.
  **되돌리기:** `api/_lib/courseServer.ts`의 `COURSE_MODEL`, `effort` 변경. 패키지 제거는 `npm uninstall @anthropic-ai/sdk` + 이 파일 삭제.
- **결정:** 후보 목록은 **브라우저에서** 이미 받은 데이터로 만들어 서버에 보냄(종류별 최대 30곳; 서버는 40곳·글자 수 제한). 서버가 서울시 데이터를 다시 받지 않음.
  **이유:** 함수 실행마다 행사 전체 페이지를 받으면 느리고 서울시 API 호출이 늘어남. 서버는 받은 목록 밖 id를 버리므로 "우리 데이터만" 원칙은 유지.
  **위험:** 사용자가 요청 본문을 조작하면 엉뚱한 이름을 넣을 수 있지만 그 결과는 본인 화면에만 보임(공유·저장 없음).
- **결정:** "다른 곳으로"는 AI를 다시 부르지 않고 규칙(같은 종류 중 앞 정류장에서 가까운 곳)으로 즉시 교체. "다시 짜기"는 현재 정류장을 빼고 AI에 다시 요청(입력창으로 돌아가지 않음).
  **이유:** 비용 보호 + 반응 속도. 시안은 "다시 짜기 → 입력창"이었음.
  **되돌리기:** `CourseRemote.tsx` `retry()`를 `setStage('input')`으로.
- **결정:** 호출 비용 보호 = 같은 입력 캐시(서버 1시간·브라우저 세션) + 서버 제한(클라이언트당 3초에 1번, 10분에 8번; 초과 시 429 → 화면은 규칙 코스로 대체) + 브라우저에서 3초 간격. 규칙 코스는 제한하지 않음.
  **위험:** 서버 메모리 기반이라 Vercel 인스턴스가 여러 개면 인스턴스별로 따로 셈(완벽한 제한 아님). 확실히 하려면 KV 저장소가 필요 — 외부 서비스 설정이라 하지 않음.
- **결정:** 리모컨 버튼은 탠저린 채움이 아니라 CTA 규칙(#1: 잉크 → hover 시 탠저린 + 잉크 아이콘). 시안의 탠저린 버튼 + 흰 아이콘은 §2.0.1 "탠저린 위 글자는 잉크", 사용처 목록과 충돌.
  **되돌리기:** `course-remote.css` `.v3-course__fab` 배경.
- **결정:** 시안의 가운데 정류장 "식사·쉬어가기"(더미 데이터)는 지시대로 문화공간으로 대체. 지도 페이지 맥락("지금 내 주변에서")은 위치 정보를 쓰지 않으므로 미리 채우지 않음.
- **결정:** 규칙 코스에서 상황 단어(친구, 데이트, 저녁, 주말 등)는 키워드로 쓰지 않음. 장소 단어(예: 성수)가 공간·야경에만 맞으면 그 근처 행사로 시작.
  **이유:** 실데이터 확인 중 "친구랑 성수"가 제목에 '친구'가 든 종로 행사를 고르는 문제 발견.
- **결정:** 지도 딥링크 `/map?sel=<kind>:<id>` 추가(기존 `?cat=야경명소&spot=` 방식과 같은 "주소로 처음 상태" 방식).
