  **되돌리기:** `components/mypage/selectors.ts` `rank()`에서 예정 행사(`eventStatus(...).kind === 'upcoming'`)에 별도 순위를 주면 됨.
- **결정:** 살아 있는 찜 카드는 공용 카드의 하트(♥, "찜 해제")로 삭제하고, "찜 삭제" 텍스트 버튼은 종료/불러올 수 없는 카드에만 둠. 테스트도 이에 맞춤.
  **이유:** 시안 M1이 그렇게 그려져 있고 홈·목록 카드와 동작이 같아짐.
  **되돌리기:** `pages/MyPage.tsx` 카드에 삭제 버튼 추가.
- **결정:** 데이터가 아직 안 왔거나 API가 실패한 종류의 찜은 "불러올 수 없음"으로 판정하지 않고 저장된 정보만 보여 줌(`pending`).
  **이유:** 네트워크 오류로 멀쩡한 찜을 "사라짐"으로 보이면 안 됨(행사 ID 이전 때와 같은 원칙).

- **결정:** 빈 화면 오른쪽 바로 가기 3개 = 이번 주 무료 행사 · 곧 마감 · 지금 켜진 야경 N(검색 패널과 같은 이름·규칙). 시안의 "곧 마감되는 전시"는 검색 칩 이름 "곧 마감"으로 통일.

### [4] 공간·야경 안정 ID
- **결정:** ID = 공간 `s<NUM>`, 야경 `n<NUM>`. API에 FAC_CODE가 없음(원본 필드 목록 확인). NUM은 실데이터에서 공간 1,100/1,100, 야경 51/51 모두 겹침·빈 값 없음, 배열 순서와도 다름.
  **이유:** 접두어를 붙여 옛 순번 ID(숫자만)와 절대 헷갈리지 않게 함 → 이전 대상·오래된 링크를 확실히 구분.
  **위험:** NUM이 서울시 데이터 갱신 때 다시 매겨지는지는 하루 데이터로만 확인해서 **장기 안정성은 미확인**. 며칠 뒤 같은 장소의 NUM이 같은지 한 번 비교해 보는 걸 권장.
  **되돌리기:** `utils/placeId.ts`의 `spaceId`/`spotId`만 바꾸면 전체가 따라감(이전은 다시 실행되지 않으므로 플래그 `nolseoul-favorites-places-version` 삭제 필요).
- **결정:** 재매칭 순서 = ① 이름+주소가 정확히 1곳 ② 이름이 정확히 1곳. 못 찾거나 여러 곳이면 `legacy-<옛 id>` + orphan으로 남김(삭제 안 함).
  **이유:** 지시대로 이름+주소가 기본이고, 주소 표기만 바뀐 경우를 살리려고 이름 단독(유일할 때만) 추가. 실데이터에서 이름이 겹치는 공간은 1,100곳 중 4개 이름뿐.
  **되돌리기:** `utils/placeFavoritesMigration.ts` `pick()`에서 이름 단독 단계 제거.
- **결정:** 백업 키 `nolseoul-favorites-v2-backup`, 완료 플래그 `nolseoul-favorites-places-version`="1"(행사 이전 플래그와 독립).
- **결정:** 이전 컴포넌트는 옛 공간·야경 찜이 있을 때만 붙어서 공간 데이터(1,100곳, 약 2MB)를 모든 페이지에서 불러오지 않음.
- **결정:** 옛 순번 링크(`/space/12`)는 행사 때와 같게 "오래된 링크라 문화공간을 찾을 수 없습니다." 표시. 옛 `/night?spot=3`, `/map?...&spot=3`은 조용히 무시(목록만 보임).
